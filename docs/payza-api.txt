Payzaapi API
Accept M-Pesa, mobile money, card, bank and crypto payments in 14 African currencies with one REST API. Then pay out, refund, bill on a schedule and run your POS from the same integration.
Quickstart
Take a test payment in about five minutes.
Accept payments
M-Pesa prompts, hosted checkout and crypto.
Webhooks
Get notified the moment a payment settles.
How a payment works
Your server calls 
POST /api/v1/pay
 with the amount, currency and customer.
For KES we send an M-Pesa prompt to the customer's phone. For every other case you redirect the customer to the 
payment_url
 we return.
The customer approves the payment on their phone or on our checkout page.
We send a signed 
webhook
 to your 
callback_url
, and you fulfil the order.
Base URL
All endpoints live under 
https://payzaapi.co.ke/api/v1
. Requests and responses are JSON, over HTTPS only.
Quickstart
Create an account
 at 
payzaapi.co.ke
 and verify your email.
Get test keys
 from 
Dashboard → API keys
. You get a public key (
pk_test_…
) and a secret key (
sk_test_…
).
Create a test payment
 with the request on the right. In test mode it succeeds instantly and your 
callback_url
 receives a real, signed webhook.
Handle the webhook
 by 
verifying its signature
 and marking the order as paid.
Go live
 by swapping in your 
pk_live_
 and 
sk_live_
 keys. Nothing else changes.
Keep your keys in environment variables such as 
PAYZA_PUBLIC_KEY
 and 
PAYZA_SECRET_KEY
, which is what every example on this page reads.

Authentication
Authenticate every request with your key pair in two headers. Create, rotate and revoke keys in 
Dashboard → API keys
.
Headers
X-Public-Key
header
Required
Your public key, 
pk_test_…
 or 
pk_live_…
.
X-Secret-Key
header
Required
Your secret key, 
sk_test_…
 or 
sk_live_…
.
Call the API from your server only.
 Your secret key can move money out of your wallet. Never put it in a website, mobile app or public repository. If it leaks, revoke it in the dashboard straight away.
Response 401 Unauthorized
Copy
{
    "success": false,
    "message": "Invalid API credentials."
}
Test and live mode
Test and live use the same URLs. The key prefix decides the mode.
Mode
Keys
What happens
Test
pk_test_
sk_test_
No money moves. Payments succeed instantly, and your 
callback_url
 gets a real signed 
payment.success
 webhook with 
"gateway": "test"
. Verify and the webhook log work as in live.
Live
pk_live_
sk_live_
Real M-Pesa prompts, mobile money, card, bank and crypto payments. Settled funds land in your wallet.
Test mode only simulates success. To exercise your failure handling, POST a sample 
payment.failed
 body (see 
payload
) to your own endpoint, signed with your webhook secret.
Errors
Every response includes 
success
. When it's 
false
, 
message

Status
Meaning
What to do
400
422
A field is missing or invalid
Fix the request using 
message
401
Keys missing or invalid
Check both headers and the key mode
403
Account suspended, currency not enabled, the request came from an IP that isn't on your 
IP whitelist
 (

), or a payout is over a limit set on your account (
error_code: limit_exceeded
)
See 
message
; for IP errors, add the 
your_ip

404
Not found on your account
Check the reference or ID
405
Wrong HTTP method
Use the method shown in these docs
409
Conflict, such as a reused 
reference
Use a new unique value
429

Wait for 
Retry-After

500

Temporary problem on our side or the payment network

Rate limits and pagination
Each API key can make 
100 requests per 60 seconds
. Past that you get 
429
 with a 
Retry-After
 header. Rely on webhooks instead of polling to stay well under the limit.
List endpoints are paginated. Pass 
page
 and 
per_page
 in the query string, and read the 
pagination
 object in the response.
Query parameters
page
integer
Optional
Page number, starting at 1. Default 
1
.
per_page
integer
Optional
Results per page. Default 
20
, maximum 
100
.

        "…"
    ],
    "pagination": {
        "page": 1,
        "per_page": 20,
        "total": 57,
        "total_pages": 3
    }
}
Create a payment
POST
/api/v1/pay
Starts a payment and returns its 
reference
 and a 
payment_url
. What happens next depends on the currency:
KES:
 an M-Pesa prompt goes to 
customer.phone
 straight away. Set 
stk_push
 to 
false
 to let the customer choose Airtel Money, Telkom, Equitel or card on our 
hosted checkout
 instead.
All other currencies:
 redirect the customer to 
payment_url
.
A payment stays payable for 30 minutes (see 
expires_at
).
Body parameters
amount
number
Required
Amount in the main unit, e.g. 
1000
 for KES 1,000. Minimums: KES 1, NGN 100, GHS 1, TZS 500, XOF 100, USD 0.50.
currency
string
Optional
Three-letter code, default 
KES
. See 
currencies
. Charging in a currency other than your account's home currency needs a multi-currency subscription, or you get 
403
.
customer.email
string
Required
Customer's email address.
customer.name
string
Optional
Customer's name. Shown on receipts and in your dashboard.
customer.phone
string
Required for KES
Kenyan mobile number, as 
254712345678
 or 
0712345678
. With an M-Pesa prompt it must be a Safaricom number (07xx or 01xx).
callback_url
string
Required
HTTPS URL on your server that receives the 
webhook
.
reference
string
Optional
Your own unique ID for this payment, such as an order number. Reusing one returns 
409
. Generated for you if omitted.
stk_push
boolean
Optional
KES only. Default 
true
 sends the M-Pesa prompt. 
false
 skips it so the customer picks a network on 
payment_url
.
redirect_url
string
Optional
Where hosted checkout sends the customer after paying.
cancel_url
string
Optional
Where hosted checkout sends the customer if they cancel.
description
string
Optional
Shown to the customer and on your statement.
metadata
object
Optional
Any key-value data you want back. It is returned unchanged in every webhook for this payment.
Response fields
data.reference
string
Store this. You'll use it to 
verify
 and to match webhooks.
data.payment_url
string
Hosted checkout page for this payment. Always returned, including for KES M-Pesa prompts.
data.crypto_payment_url
string
Sends the customer straight to 
crypto checkout
.
data.fee
data.net_amount
number
Our fee, and what reaches your wallet.
data.status
string
pending
 in live mode until the customer pays. 
success
 immediately in test mode.
data.stk_sent
boolean or null
KES only: whether the M-Pesa prompt was sent.

Hosted checkout
Our checkout page handles every method for you: mobile money in each country, card, bank transfer and crypto. Use it for all non-KES payments, and for KES when your customer might not be on Safaricom.
Create the payment with 
redirect_url
 and 
cancel_url
 (and 
"stk_push": false
 for KES).
Redirect the customer's browser to 
data.payment_url
.
They pick a method and pay. We send them back to your 
redirect_url
.
Fulfil the order from the 
webhook
, not from the redirect. A customer can close the tab before being redirected.
On your 
redirect_url
 page, call 
verify
 with the reference if you want to show "Payment received" immediately.

Verify a payment
GET
/api/v1/verify/{reference}
Returns the current status of a payment. In live mode, if the payment is still pending we check with the payment network before answering, so the result is as fresh as possible.
Use it on your thank-you page, and as a safety net if a webhook hasn't arrived after a few minutes. It's also the right way to confirm an amount before shipping high-value goods.
Path parameters
reference
string
Required
The payment reference, in the URL path.
Statuses
pending
Waiting for the customer
success
Paid. 
paid_at
 is set
failed
Declined, timed out or wrong PIN
cancelled
The customer cancelled

Crypto payments
Every payment includes a

crypto_payment_url

The payment was declined or timed out

Verify signatures
Every webhook carries an 
X-Payza-Signature
 header: an HMAC-SHA256 of the 
raw request body
, hex-encoded, using your account's 
Webhook Signing Secret
.
Find your secret in 
Dashboard → API keys → Webhook Signing Secret
, along with ready-to-copy code and your recent deliveries. It's unique to your account and separate from your API keys. If you regenerate it, update your server at the same time.
Read the raw body before parsing JSON. Re-encoding changes the bytes and breaks the signature.
Compute the HMAC with your secret and compare it to the header with a constant-time comparison.
If they don't match, reply 
401
 and ignore the request.
Webhook handler

<?php
$raw      = file_get_contents('php://input');
$received = $_SERVER['HTTP_X_PAYZA_SIGNATURE'] ?? '';
$expected = hash_hmac('sha256', $raw, getenv('PAYZA_WEBHOOK_SECRET'));
if (!hash_equals($expected, $received)) {
    http_response_code(401);
    exit;
}
$event = json_decode($raw, true);
if ($event['event'] === 'payment.success') {
    // Skip if this order is already marked paid (webhooks can repeat)
    markOrderPaid($event['reference'], $event['amount'], $event['currency']);
}
http_response_code(200);
echo 'OK';
import express from 'express';
import crypto from 'node:crypto';
const app = express();
// Keep the raw body: the signature is computed over the exact bytes
app.post('/webhooks/payza', express.raw({ type: 'application/json' }), (req, res) => {
  const expected = crypto
    .createHmac('sha256', process.env.PAYZA_WEBHOOK_SECRET)
    .update(req.body)
    .digest('hex');
  const received = req.get('X-Payza-Signature') || '';
  const valid = received.length === expected.length &&
    crypto.timingSafeEqual(Buffer.from(received), Buffer.from(expected));
  if (!valid) return res.sendStatus(401);
  res.sendStatus(200); // reply first, then process
  const event = JSON.parse(req.body);
  if (event.event === 'payment.success') {
    markOrderPaid(event.reference, event.amount, event.currency);
  }
});
import hashlib, hmac, os
from flask import Flask, request, abort
app = Flask(__name__)
@app.post("/webhooks/payza")
def payza_webhook():
    raw = request.get_data()  # raw bytes, not request.json
    expected = hmac.new(
        os.environ["PAYZA_WEBHOOK_SECRET"].encode(), raw, hashlib.sha256
    ).hexdigest()
    received = request.headers.get("X-Payza-Signature", "")
    if not hmac.compare_digest(expected, received):
        abort(401)
    event = request.get_json()
    if event["event"] == "payment.success":
        mark_order_paid(event["reference"], event["amount"], event["currency"])
    return "OK", 200

Subscriptions
POST
/api/v1/subscriptions
Subscribes a customer to a plan. The first charge happens one interval from now, then repeats.
KES plans
 send an M-Pesa prompt to 
customer_phone
 on each billing date, which the customer approves.
USD plans
 charge the customer's saved card automatically. The customer must first complete one USD card payment through 
POST /api/v1/pay
 with the same email, which saves the card.
Body parameters
plan_id
integer
Required
An active plan.
customer_name
string
Required
Subscriber's name.
customer_phone
string
Required for KES
Receives the M-Pesa prompt each period.
customer_email
string
Required for USD
Used to find the saved card.
customer_id
integer
Optional
Link to a 
customer
 record.
GET
/api/v1/subscriptions
Lists subscriptions. Filter by 
status
 (
active
, 
paused
, 
cancelled
, 
past_due
) or 
plan_id
.
POST
/api/v1/subscription-cancel
Body parameters
id
integer
Required
Subscription ID.
action
string
Optional

 (default) or

Install on WooCommerce
In WordPress, go to 
Plugins → Add New → Upload Plugin
, choose the zip and activate it.
Open 
WooCommerce → Settings → Payments → Payza
 and paste your keys.
Place a test order with test keys. It should move to 
Processing

Install on WHMCS
Upload the zip's contents to your WHMCS root so 
modules/gateways/payza.php
 is in place.
In 
Configuration → Payment Gateways
, activate Payza and enter your keys.
Each invoice's 
callback_url
 is set to 
/modules/gateways/callback/payza.php
 automatically.
Go-live checklist
Your server verifies 
X-Payza-Signature
 on every webhook and rejects mismatches.
Your webhook handler replies 
200
 within 10 seconds and ignores events it has already processed.
Orders are fulfilled from the webhook (or 
verify
), never from the customer's redirect alone.
You check 
amount
 and 
currency
 against the order before fulfilling.
Every payment uses a unique 
reference
, stored against your order.
Keys live in environment variables on your server, and the secret key is never sent to a browser or app.
Your 
callback_url
 is HTTPS and doesn't redirect.
You've swapped test keys for 
pk_live_
 and 
sk_live_
 keys.
FAQ
How do I accept Airtel Money, Telkom or Equitel in Kenya?
Create the payment with 
"stk_push": false
 and redirect the customer to 
payment_url
. They choose their network on our checkout page.
When should I use stk_push true or false?
Use 
true
 (the default) when you know the customer is on Safaricom and want the fastest payment, since the prompt appears on their phone within seconds. Use 
false
 when you don't know their network.
Does payment_url work for Safaricom customers too?
Yes. The checkout page lists M-Pesa alongside every other method, so one link works for everyone.
Why do I get 403 for some currencies?
Your account charges in its home currency by default. Charging in other currencies needs a multi-currency subscription, which you can turn on in your dashboard.
How long does a customer have to pay?
30 minutes from creation, shown in 
expires_at
. After that, create a new payment with a new reference.
Can I reuse a reference?
No. Every payment needs a unique reference, and a repeat returns 
409
. If a customer retries, add a suffix such as 
ORDER_1001_2
.
My webhook isn't arriving. What should I check?
Check the 
delivery log
 for the HTTP status we received. Common causes: the URL redirects (we don't follow redirects), a firewall blocks POST requests, the handler takes over 10 seconds, or it returns 
401
 because signature verification uses the wrong secret. Fix it, then resend.
Which Kenyan phone formats are accepted?
254712345678
, 
0712345678
 and 
+254 712 345 678
 all work, as do 01xx numbers. M-Pesa prompts need a Safaricom number.
